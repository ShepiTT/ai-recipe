# 部署到阿里云服务器

> 场景：Ubuntu + Nginx，80 端口原本跑着别的站点，现在要换成 ai-recipe。
> 目标：**ai-recipe 独占 80**，原站点先备份再下线。
> 方案：Nginx 整站反代到本地 3000。网页版和小程序 API 共用一套配置，
> 不暴露 3000 端口，也不用改安全组。

---

## 0. 先备份原站点（别跳过）

```bash
ssh root@<你的服务器IP>
```

```bash
# 备份 Nginx 配置
mkdir -p /root/backup-$(date +%F)
cp -r /etc/nginx/sites-available /root/backup-$(date +%F)/

# 找出原站点的文件目录并整个备份
ROOT=$(grep -oP '^\s*root\s+\K[^;]+' /etc/nginx/sites-available/default | head -1)
echo "原站点目录: $ROOT"
cp -r "$ROOT" /root/backup-$(date +%F)/site-files
ls -la /root/backup-$(date +%F)/
```

确认 `site-files` 里有东西再往下走。

## 1. 传代码

在**本机** PowerShell：

```powershell
cd "C:\Users\Administrator\Desktop\新建文件夹"
tar -czf ai-recipe.tar.gz --exclude=node_modules --exclude=.git ai-recipe
scp ai-recipe.tar.gz root@<你的服务器IP>:/root/
```

服务器上解包：

```bash
mkdir -p /opt && tar -xzf /root/ai-recipe.tar.gz -C /opt && cd /opt/ai-recipe
rm -f src/data/db.json     # 不要把本机账号带上服务器，从空数据开始
```

## 2. 装 Node 与依赖

```bash
node -v 2>/dev/null || (curl -fsSL https://deb.nodesource.com/setup_20.x | bash - && apt-get install -y nodejs)
cd /opt/ai-recipe && npm install --omit=dev
```

## 3. 配置 .env

```bash
cd /opt/ai-recipe && nano .env
```

```
PORT=3000
DEFAULT_PROVIDER=deepseek

# ⚠️ 现在是明文 HTTP，先别填真实 Key。等 HTTPS 上了再改成 0 并填 Key
MOCK_MODE=1
DEEPSEEK_API_KEY=
QWEN_API_KEY=

WX_APPID=<你的小程序 AppID>
WX_SECRET=
```

验证一下：

```bash
cd /opt/ai-recipe && node server.js &
sleep 2 && curl http://127.0.0.1:3000/api/health && kill %1
```

看到 `{"ok":true,...}` 就继续。

## 4. pm2 守护

```bash
npm install -g pm2
cd /opt/ai-recipe && pm2 start server.js --name ai-recipe
pm2 save && pm2 startup     # 按它打印的那行再执行一次，开机自启
pm2 logs ai-recipe --lines 20
```

## 5. Nginx 换成 ai-recipe（原站点下线）

```bash
cat > /etc/nginx/sites-available/default <<'NGINX'
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    server_name _;

    # 整站反代到 Node：/ 是网页版，/api/ 是接口，一套配置搞定
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 生成菜谱可能要一两分钟，默认 60s 会 504
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }
}
NGINX

nginx -t && systemctl reload nginx
curl http://127.0.0.1/api/health
```

再从外面验证：`curl http://<你的服务器IP>/api/health`

> 原站点到这里就不再对外了，但**文件还在**（`$ROOT` 目录 + 备份）。
> 确认不要了再删：`rm -rf "$ROOT"`。建议先放几天。

## 6. 小程序切到服务器

`miniprogram/utils/config.js`：

```js
const DEV_URL = 'http://<你的服务器IP>';   // 走 80，不带端口
```

开发者工具重新编译 → 「预览」→ 手机扫码。

> 手机上打开开发版后，右上角「···」→ **打开调试**，否则仍会校验合法域名。

---

## ⚠️ 明文 HTTP 期间的纪律

登录 token 和密码都在公网上明文传输，拿到 token 就能冒充你。所以：

- `MOCK_MODE=1`，**不填真实 API Key**（这样「花你的钱」这条风险不成立）
- 用**专用测试账号**，密码别和别处重复
- 别在公共 WiFi 调试，别把这个地址发给别人

HTTPS 上了之后，把测试账号**改一次密码**——改密会让所有旧会话立即失效，等于把明文期可能泄露的 token 全部作废。

---

## 后续：备案下来之后

1. 域名 A 记录指向 <你的服务器IP>
2. 阿里云签发免费 SSL 证书，传到服务器
3. Nginx 加 443 server 块（证书路径 + 同样的 proxy_pass），80 改成 301 跳 443
4. `config.js` 换成 `PROD_URL = 'https://你的域名'`
5. 小程序后台 → 开发管理 → 服务器域名 → request 合法域名填该域名
6. `.env` 里 `MOCK_MODE=0` 并填真实 Key
