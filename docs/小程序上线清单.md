# 微信小程序上线清单

> 前提：个人主体 · 原生小程序 · 服务器与域名从零开始

## ⏱ 关键路径：ICP 备案

备案要 **1–20 个工作日**（通常 3–7 天），是整条链路上最慢的一环，**今天就该启动**。
代码改造可以和备案并行，不用等。

---

## 第 1 步：你要自己做的（我做不了）

### 1.1 买服务器（当天）

- 阿里云 / 腾讯云 **轻量应用服务器**，2核2G 足够
- **必须选中国大陆地域**（香港、新加坡等境外节点无法备案）
- **购买时长 ≥ 3 个月**，否则不满足备案要求
- 系统选 Ubuntu 22.04 或 Debian 12

### 1.2 买域名 + 备案（当天启动，然后等）

- 域名在**同一家云厂商**买，备案流程能自动带出服务器信息，省事
- `.com` / `.cn` 都行，约 ¥30–60/年
- 在云厂商控制台提交 **ICP 备案**，个人主体需要：身份证、手机号、邮箱、幕布拍照（厂商寄或 App 拍）
- 备案期间服务器可以先用着，只是域名不能对外提供服务

### 1.3 注册小程序（可与备案并行）

1. <https://mp.weixin.qq.com> → 立即注册 → 小程序 → 个人主体
2. 拿到 **AppID**（`微信开发者ID`）和 **AppSecret**（开发管理 → 开发设置）
3. 选类目 —— **这一步最容易卡**，见下方「类目与合规」
4. 把 AppID / AppSecret 发我，我配到后端（**AppSecret 不要贴到聊天里以外的地方，也不要提交进代码仓库**）

### 1.4 类目与合规（个人主体的难点）

| 事项 | 说明 |
|---|---|
| AI 生成内容类目 | 个人主体基本申请不下来，需要算法备案等企业资质 |
| 可行方向 | 按产品实质申报，例如「工具 → 效率」类的菜谱/备餐管理工具 |
| 内容安全 | 有用户输入就**必须**接 `security.msgSecCheck`，不接大概率驳回 |
| 隐私协议 | 小程序需在「用户隐私保护指引」里声明收集了哪些信息 |

> ⚠️ 按产品**实际是什么**申报。如果核心就是 AI 生成，个人主体这条路走不通，得转企业主体。

## 第 2 步：我来做的代码改造

| 项 | 状态 | 说明 |
|---|---|---|
| 微信登录接口 | 待做 | `wx.login` → `code2session` 换 openid，替换用户名密码 |
| 内容安全检测 | 待做 | 封装 `security.msgSecCheck`，用户输入与 AI 输出都过一遍 |
| 小程序前端 | 待做 | 原生 WXML/WXSS，重写全部页面 |
| 后端 API | 小改 | 业务逻辑可直接复用，只换登录方式 |
| 部署脚本 | 待做 | Nginx 反代 + HTTPS + 进程守护 |

**能直接复用的**：`src/services/`（菜谱生成、详情、归一化）、`src/llm/`（模型调用、JSON 容错）、`src/config.js`（模型配置）——这部分是项目的核心价值，一行不用改。

**必须重写的**：`public/` 下约 2500 行网页前端。小程序不认 HTML/CSS/DOM。

---

## 第 3 步：部署（备案下来之后）

1. 服务器装 Node 20+、Nginx
2. Nginx 反代到 `127.0.0.1:3000`，配 HTTPS（云厂商免费 SSL 证书）
3. `pm2` 或 `systemd` 守护 Node 进程
4. 小程序后台 → 开发管理 → 开发设置 → **服务器域名** → `request 合法域名` 填 `https://你的域名`
   - 只能填域名，**不能带端口、不能用 IP、必须 443**

---

## 第 4 步：提审

- 开发者工具上传代码 → 微信后台提交审核
- 审核 1–7 天，被驳回会给具体理由，按理由改
- 首次提审建议把功能说明写清楚，附测试账号

## 一个需要你决定的产品问题

现在的设计是**每个用户填自己的 API Key**。搬到小程序上有矛盾：

- **让用户填 Key**：体验极差（谁会为了看菜谱去注册 DeepSeek），但责任清晰，更像纯工具
- **你统一出 Key**：体验正常，但成本你承担，而且「你在对外提供 AI 服务」的属性更强，合规要求更高

上线前要定这个，它同时影响成本、体验和类目申报。
